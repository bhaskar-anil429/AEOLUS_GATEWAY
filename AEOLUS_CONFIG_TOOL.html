Firmware updates (LTE, automatic)

The gateway reads a small version file (latest.json: {"version":"V1.73","url":"https://…/AEOLUS_V1.73.bin"}) on its first cycle after a restart and then every N days. If it lists a newer version, the gateway downloads the image, restarts into it and keeps it once it reaches the cloud; otherwise it goes back to the previous firmware. Running: —
Runs at the end of the gateway's next cycle, after this config window closes. Each URL gets at most 3 tries.

Sensor firmware (sent over Bluetooth)

The gateway downloads a PLP sensor update file (.ncd, the file the phone app sends) and sends it to each sensor on another version after reading its recordings. The sensor restarts to install it; the next visit confirms the new version. A sensor entry in the version file above does the same automatically for sensors on an older version. Now: —
New firmware is running unconfirmed. The gateway keeps it automatically once it reaches the cloud, and goes back to the previous firmware after 3 cycles without it. Confirm running image keeps it now.

Firmware update (BLE)

Uploads to the spare slot, reboots into it on a trial basis. After the device reboots, reconnect and press Confirm running image — an unconfirmed image rolls back automatically on the next reboot.
